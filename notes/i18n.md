# Languages of the web pages

The site is in Armenian (hy), English (en) and
Russian (ru). Started 2026-11-22.

## Decisions (the user's)

- A first visit takes the browser's language
  (`navigator.languages`; anything but hy, en or
  ru gives Armenian). The one picked last is kept in
  the browser (`nxgir-ui-lang`).
- The language is in every path: `/hy/library`,
  `/en/read/<book>?line=3`, `/ru/blog/<slug>`. A
  link opens the page in the language it was shared
  in.
- The per-page pickers stay for now (blog, comics,
  map, Features, author and book cards, Reference,
  announcements, word meanings). They start from
  the language of the address; a pick holds for
  that kind of page until the site's language
  changes (`pagePick` in `app.js`), and is not kept
  after a reload.
- Russian word meanings: English, until there are
  Russian ones.

## How it works

- `web/i18n.js`, loaded before `app.js`:
  - `LANGS = ["hy", "en", "ru"]` (as `LANGS` in
    `nxgir_blog.py`; a test checks it);
  - `LANG`: from the address, else kept, else the
    browser's;
  - `UI`: the words of the pages, `UI.hy`, `UI.en`,
    `UI.ru` with the same keys; a value is a string,
    a list (`months`, `st.cols`) or a function of
    numbers (`t("n.book", 3)`; `enN()` and `ruN()`
    choose the plural);
  - `t(key, ...args)`: the word in `LANG`, else in
    English, else in Armenian.
- `app.js`:
  - pages are still named `"#/library"` in the code;
    `setRoute()` / `goTo()` / `pathOf()` put
    `/<LANG>` in front, `hashNow()` takes it off,
    `inLang(l, "#/x")` is the page in another
    language;
  - at start an old address (`/#/x`, `/x`,
    `/blog/<slug>/<lang>`, `/map/<place>/<lang>`,
    `/features/<lang>`) is replaced by its new
    path;
  - the language slider (`langButton()`, Հայ · Eng
    · Рус in the top bar; on a phone a row under
    the brand, with the full names) links the page
    shown in each language: plain links, so back
    works; the thumb is a `::before` moved by `--i`;
    the globe button beside it hides and shows it
    (`nxgir-lang-bar`, shown at first);
  - `route()` → `followLang()`: when the address
    has another language, `LANG` changes, it is
    kept, `<html lang>` is set, and `langchange`
    redraws what is drawn once (the ☰ menu, the
    tab bar and its More sheet, the theme and view
    buttons); then the page is drawn as always;
  - `<html lang>` is `LANG`, so the interface needs
    no `lang` attribute; the text of the books and
    the names of authors and books (Armenian) keep
    `lang: "hy"`.
- `build-site.py`: the pages for search engines
  under `<lang>/`; the ones with Armenian text
  (books, volumes, authors, Library, Reference)
  under `hy/` only, the others (top page, blog,
  comics, Features, Map, the lists, Timeline) in
  each language with `hreflang` links. The root
  `index.html` names the three top pages, and
  itself as `x-default`. A path with no file gets
  `404.html`, the app, which reads the address.

## Adding words

1. Add the key to `UI.hy`, `UI.en` and `UI.ru` in
   `web/i18n.js`, at the end of the group it
   belongs to (the groups are comments).
2. Use `t("key")` in `app.js`. Never write words of
   the interface in `app.js`.
3. `python3 -m pytest tests/test_i18n.py`: same
   keys and kinds in each language, every
   `t("...")` known.

Armenian follows the house style (Նախագիր in
Armenian text, nxGir in English and Russian; see
CLAUDE.md, The name). Claude wrote the English and
Russian, and the Armenian of the pages that were
only in English (Contribute, Statistics, Offline,
the reader's tools): **the Armenian needs a
reader's check**.

## Not translated yet

- The Timeline's events (`timeline.tsv`, English;
  the page says so in hy and ru). A `title_hy`,
  `text_hy`, ... column per language would do it.
- On Statistics, the names and notes of the
  limits (from `nxgir_limits.py`, English).
- The error report itself (the GitHub issue): kept
  in English for the maintainer; the form is
  translated.
- Author and book names on the Library and search
  pages stay Armenian (the search finds them by
  their English and Russian names too).
- Help texts from the Grabar helpers (`Source:`
  lines) and server errors.
- The terminal reader (curses): not part of this.
- `manifest.webmanifest`: one name for every
  language.
